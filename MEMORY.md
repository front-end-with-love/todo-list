## 2. Approved Decisions

Подробные требования и определения находятся в `PROJECT_BRIEF.md` и `docs/architecture.md`:

- Продукт: русскоязычный To-Do List, строго четыре пользовательские функции, без расширения scope.
- Стек: HTML5, CSS3, Vanilla JavaScript, нативные ES Modules, `localStorage`, Playwright Test.
- CSS: ITCSS (Settings → Generic → Elements → Objects → Components) + BEM; JS: MVC-lite + Repository.
- Composition root `app.js` создаёт View и Repository и передаёт их Controller; Controller импортирует только Model. Brief §4.4 допускает более широкий набор зависимостей, выбранное сужение согласовано.
- Фокус: после добавления (Enter или кнопка) и после пустой отправки — всегда поле ввода; после toggle — чекбокс той же задачи; после удаления — следующая задача, иначе предыдущая, иначе поле ввода.
- ID задачи — только `crypto.randomUUID()`; fallback нет, при отсутствии API задача не создаётся и показывается сообщение.
- Repository отдаёт результат-объекты (`{tasks,error}` / `{ok,error}`, коды `unavailable`/`corrupt`/`write-failed`), ловит доступ к `localStorage`, `getItem`, `JSON.parse` и `setItem`; повреждённые данные при запуске не перезаписываются.
- `.gitignore` включён в дерево с исключениями `.DS_Store`, `__MACOSX/`, `._*`, `node_modules/`, `test-results/`, `playwright-report/`, `.history`, `FIRST_PROMPT.md`; `package-lock.json` и файлы шрифта `fonts/` не игнорируются.
- Одна модель DeepSeek; без субагентов. Git/GitHub/deploy выполняет пользователь.
- Типографика (решение 2026-11-13, `PROJECT_BRIEF.md` §7.5): взяты из разбора `uprock.ru` начертание 600 вместо 700 у `h1`, трекинг −0.02em только у `h1`, интерлиньяж 1.15 у `h1`, микро-лейбл подписи поля (прописными, 12 px, 600). Не взяты display-кегли, отрицательный трекинг на основном тексте и кириллических прописных. Разбор — `docs/typography-uprock-review.md`.
- Гарнитура (решение 2026-11-13, `PROJECT_BRIEF.md` v4.2): Inter 4.1 подключена локально из `fonts/` — начертания 400/500/600, сабсеты кириллицы и латиницы, `font-display: swap`, preload кириллических сабсетов, системный fallback с согласованными метриками (`size-adjust`/`ascent`/`descent-override`). Внешних запросов нет; лицензия SIL OFL 1.1 лежит в `fonts/OFL.txt`.

## 3. Known Issues / Open Items

- Формула Homebrew `node@22` помечена deprecated (актуальный LTS — Node 26); переход на новую LTS-линию требует отдельного согласования и повторного прогона тестов.
- Исходный архив референса (`build.zip`) в репозиторий не входит: свежий клон не содержит референса, все извлечённые из него решения зафиксированы в `PROJECT_BRIEF.md` §7 и `docs/design-system.md`.
- Шрифты PP Neue Montreal не подключены (лицензия не подтверждена). Гарнитура проекта — Inter 4.1 (SIL OFL 1.1) из `fonts/`: бинарные файлы шрифта лежат в репозитории и должны попасть в коммит, а лицензия `fonts/OFL.txt` — рядом с ними.
- Набор подключённых начертаний Inter (400/500/600) должен совпадать с токенами весов: при отсутствии файла браузер молча подставляет ближайшее начертание и дизайн меняется без ошибок в консоли. Это закрыто тестом «подключены отдельные файлы для каждого начертания».
- Границы `unicode-range` в `css/settings/fonts.css` подобраны так, чтобы русский интерфейс тянул только кириллические сабсеты; при появлении латинских букв в интерфейсе латинский файл подгрузится сам, а при смене диапазонов тест на отсутствие `-latin.` упадёт — это ожидаемый сигнал, а не сбой.
- Проверка выполнена в Chromium; другие браузеры не подключались (по brief достаточно Chromium).
- Контрасты и зоны нажатия проверены расчётом и измерением в браузере, отдельного автоматического axe-аудита нет.
- Проверка «200%» — эмуляция text-only zoom через увеличение корневого `font-size` с проверкой reflow; браузерный zoom всего вьюпорта не тестировался.
- Доступное имя кнопки удаления включает текст задачи; при очень длинном тексте имя тоже длинное (редактирования задач нет, поэтому имя не устаревает).
- Ключ `todo-list.tasks.v1` (`js/tasks/task-repository.js` и константа в `tests/e2e/tasks.spec.js`) не содержит префикса origin. На GitHub Pages все работы аккаунта делят origin `front-end-with-love.github.io`, поэтому ключ стоит сделать уникальным; решение не принято.
